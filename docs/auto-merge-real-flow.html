The real end-to-end flow

The important boundary is simple: Fullsend decides whether semantic context permits a request; GitHub decides whether and how that request can merge.

Who checks what?

GitHub / SCM

Mechanical merge policy

Required checks, required reviews, conversation resolution, branch freshness, mergeability, rulesets, queue ordering, merge-group synthesis, and the final merge.

CI and merge_group triggers · PR #9 final state

Trusted host scripts

Authority boundary

Collects secret-free evidence, verifies fingerprints, selects the validated result, performs fresh semantic postflight, and submits exactly one head-matched native request.

pre-script · finalizer

OpenShell agent

Semantic judgment

Interprets evidence SCM cannot interpret reliably: whether human context still signals a hold, whether risk and review evidence are coherent, and whether the exact binding is safe to authorize.

agent boundary · decision contract

GitHub merge queue

SCM owns queue-time checks

After native auto-merge is requested, GitHub creates the merge-group revision, runs the repository’s configured checks, and decides whether to merge. The portable agent adds no custom queue callback.
