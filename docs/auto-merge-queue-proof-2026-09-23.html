04 / CONTRAST

The failed attempt explains the fix.

PR #4 was not unsafe; it exposed a configuration and tooling boundary before any merge mutation happened.

PR #4 · first queue attempt

The agent reached APPROVE, wrote a pending receipt, and attempted queue enrollment. GitHub rejected the request while repository allow_auto_merge was false. The post-script failed closed and wrote not-queued; PR #4 remained open.

Failed run ↗ · not-queued receipt ↗

PR #5 · corrected queue attempt

After repository auto-merge was enabled, a fresh exact-head PR followed the same policy. Automatic review-triggered Auto-Merge wrote a queued receipt, merge-group checks passed, and GitHub merged through the queue.

queued receipt ↗ · merge-group run ↗

Important interpretation: enabling repository auto-merge did not replace Fullsend authorization. The agent still had to pass deterministic gates, semantic approval, exact binding, fresh postflight, queue authorization, and merge-group checks. It enabled the forge operation that the existing post-script uses to enter the queue.

07 / LIMITS

What this snapshot does not claim.

Not production completion: this proves one public repository, one low-risk documentation change, one queue configuration, and one successful merge-group cycle. It does not prove policy portability across every repository, concurrency under a busy queue, recovery from an ambiguous forge response, or the final production API design.
